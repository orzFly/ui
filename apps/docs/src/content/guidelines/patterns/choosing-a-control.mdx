**A Switch acts the moment it flips. A Checkbox waits for a submit, or picks items from a set.
Exactly one of a few is a RadioGroup; exactly one of many is a Select.**

<Example of={ControlsCompared} />

On the left, the Settings demo's editor section. Its settings apply as they change, so the on-off
ones are Switches; the language new files open as has too many options to show at once, so it is a
Select; and the three ways to indent are worth seeing side by side, so they are a RadioGroup. On
the right, Mail's conversations do nothing until **Archive**, so each row has a Checkbox. Tick
one, and the box above them turns partly checked; press it to select none.

## Do and don't

<DoDont>
  <Do show={<SwitchesApplyNow />}>
    Use a Switch for a setting that applies immediately, with no Save button after it.
  </Do>
  <Dont show={<SwitchesInAForm />}>
    Put Switches in a form with a Save button: nobody can tell whether a flip already took effect.
  </Dont>
</DoDont>

<DoDont>
  <Do show={<NotifyRadioGroup />}>
    Show two to five options as a RadioGroup when people should compare them before choosing.
  </Do>
  <Dont show={<NotifySelect />}>
    Hide three options in a Select to save a few lines: the choice costs a tap to open and the
    options cannot be read side by side.
  </Dont>
</DoDont>

## Which one

| The choice | Takes effect | Use |
|---|---|---|
| One setting, on or off | Immediately | `Switch` |
| One yes or no in a form, or agreeing to terms | On submit | `Checkbox` |
| Any number of items from a set: filters, facets, a bulk selection | On apply or submit | `Checkbox` list |
| Exactly one of two to five, worth seeing together | Either | `RadioGroup` |
| Exactly one of many, or of options with long names | Either | `Select` |
| Exactly one of a list too long to scan, or one that grows with people's own data: a task, a person, a label | Either | `FilterMenu`, behind a button that shows the pick |
| A value along a range, where the exact number matters less than the feel | Either | `Slider` |
| A colour | Either | `ColorPickerPopover`, with the app's palette as `swatches` |
| One of a few views of the same thing | Immediately | `Tabs`: they switch what is shown, not a value that is saved |

The parent of a partly checked list is a Checkbox with `checked="indeterminate"`. A Switch has no
indeterminate state and no "applies later": if the setting only takes effect once
something else happens, it is not a Switch.

<Example of={ProfileChoices} />

The Settings demo's profile form keeps its choices until **Save profile**, so its one yes or no is
a Checkbox. Its time zone is one of thirteen, too many to lay out side by side, so it is a Select.

<Example of={DuplicateOf} />

A task is a duplicate of one of sixty others. A Select would make people scroll for it; people
already know a word of its title or its number, so `FilterMenu` lets them type it. The trigger is a
button that names the pick, and the menu closes on it. Use it once a list runs past what fits on
one screen, or holds things people add themselves, whose number nobody can promise; a fixed set
that fits, like the time zones above, stays a Select.

<Example of={FontSizeSlider} />

The Settings demo's font size is picked by how the code looks, not by its number, so it is a
Slider, and the line of code under it follows as it drags.

<Example of={LabelColours} />

A label's colour only tells it apart from the others, so the app's palette rides along as
swatches and most picks are one tap; the area and sliders above them are there for a colour of
one's own. Pass
`format="hex"` and `alpha={false}` when the colour is stored as a plain hex. Open the full
`ColorPicker`, without the popover, only where colour is the work itself, such as a theme editor.

## On each platform

### Desktop & pointer

- The label is part of the hit area: pair every control with a `Label` through `htmlFor`, so a
  click on the words toggles it.
- Space toggles a Switch or Checkbox; the arrow keys move within a RadioGroup, and Tab leaves it.
- Rows stay compact. A settings list reads as a column of labels with the controls on one edge.

### Touch

- The controls take their touch sizes on a coarse pointer by themselves; there is no prop to set.
  The **Touch** button above an example previews them.
- In a settings list, put the label on the leading edge and the Switch on the trailing edge, as the
  phone's own settings do.
- A Select opens a list the width of the trigger: keep option names short enough to read in it.
